# Editful plugin tools

Official build and distribution tooling for trusted Editful plugins. It bundles
TypeScript, TSX, React, the Editful SDK, and other browser-compatible npm
packages into the one self-contained `plugin.mjs` required by Editful.

## Project

Install `@editful/canvas-sdk` as a runtime dependency and
`@editful/plugin-tools` as a development dependency. Create
`editful.plugin.ts`:

```ts
import { definePluginConfig } from '@editful/plugin-tools';

export default definePluginConfig({
  id: 'acme:status-card',
  name: 'Status card',
  description: 'Adds a status card to the canvas.',
  version: '1.0.0',
  entry: './src/index.tsx',
  minAppVersion: '0.9.0',
  capabilities: ['node-kinds', 'commands', 'editor-ui'],
  assets: { icons: ['./assets/status.svg'] },
});
```

`sdkVersion` is read from the runtime API contract declared by the project's
installed `@editful/canvas-sdk` when omitted. It is intentionally independent
of npm package patch releases. Capabilities are emitted in canonical order. The
entry digest and fixed output entry name are always generated by the tool.

Network, remote-media, and external-script declarations use the manifest shape
documented in [`@editful/plugin-artifact`](../plugin-artifact/README.md). For
example, a plugin that runs a vendor's script library declares the origin in
both `network` and `scripts`:

```ts
export default definePluginConfig({
  // ...
  capabilities: ['editor-ui', 'network', 'external-scripts'],
  network: [{
    origin: 'https://maps.googleapis.com',
    methods: ['GET'],
    purpose: 'Load Google Maps data for map editors.',
  }],
  scripts: [{
    origin: 'https://maps.googleapis.com',
    purpose: "Run Google's Maps JavaScript API in map editors.",
  }],
  // Only for libraries that compile WebAssembly at runtime.
  webAssembly: { purpose: 'Compile Google Maps label placement.' },
});
```

Plugins declare only the oldest Editful release they need. Compatibility with
future Editful releases is controlled by the host's supported SDK range, so
plugin authors do not need to predict an app-version ceiling.

## Commands

```bash
editful-plugin build
editful-plugin check
editful-plugin dev --root /absolute/path/to/editful-plugins
editful-plugin pack
```

`build` publishes `dist/acme-status-card/{plugin.json,plugin.mjs,...}` through
an atomic directory swap. `check` performs the same bundle and validation
without touching `dist`.

Validation covers the artifact and manifest, and for plugins with the
`commands` capability also the commands they register: each command's
`toolbar.order` must be an integer from -1000 to 1000, which Editful requires
before it loads a plugin. To see registered commands, the tool imports the
built `plugin.mjs` and calls `register` with a recording context whose other
members are stand-ins for values that exist only inside Editful.

That evaluation runs in a separate Node process with an empty environment and
Node's permission model: it may read only the built `plugin.mjs`, and writing
files, network access, child processes, worker threads, native addons, WASI,
and the inspector are denied. It gets a 128 MiB heap and is killed after it
reports or after 5 seconds. The process still runs as your user, so it can,
for example, signal other processes; evaluate only plugins whose source you
would build anyway.

The check never fails the build on something it cannot judge. When the bundle
cannot register outside a browser, for example because `register` touches
`document`, or it keeps using stand-ins as in a loop, the command checks are
skipped with a warning. An order that is or was computed from a stand-in, such
as `context.settings.get('order') ?? 5`, is reported as a warning too. `dev` watches the project and emits an inline source
map. `pack` additionally creates a deterministic
`acme-status-card-1.0.0.editful-plugin` ZIP.

For live development against the installed production app, select a stable
**Plugins folder** in Editful and pass the exact same absolute folder to the
watcher:

```bash
pnpm dev --root "$HOME/Documents/Editful Plugins"
```

The tool writes one direct child per plugin. Editful watches that selected root
and reloads validated rebuilds.

All npm packages are bundled. Node built-ins and unresolved imports fail the
build. Auxiliary runtime chunks and assets are rejected because the current
Editful artifact contract accepts only a single module and passive SVG toolbar
icons. Inline other UI assets in source for now.
